- work-default binds Work Copilot's MCP server (`work-copilot mcp`, stdio) for laptops: `install_local.py` prints its
  `claude mcp add` line after the lock's servers, with its data directory as `WORK_COPILOT_DATA_DIR`, set per machine
  and never in shared config (KAN-380). In project scope the line uses `--scope local`, so the server never lands in
  a committed `.mcp.json`. Work Copilot reads the variable from KAN-382 on. Claude Code keeps the value the line
  gave it, so the dry run warns while the variable is unset; changing it later means re-adding the server.
- `bindings/<harness>.yaml` can mark a server `local_only: true`. `relock.py` checks it like any server, and also
  refuses a machine path in its command or args, an env value other than `${NAME}` for its own name, and a name the
  lock binds, but leaves it out of the lock, so no hangar environment or sandbox tries to start it and the harness
  digest is unchanged. Every channel prints the checkout's local servers, as no lock pins them, after checking the
  same shape again (the working tree may not be relocked) and quoting each word for the shell.
- `install_local.py --check` reports each MCP server the harness names, the lock's and the local ones: added to
  Claude Code where its printed line adds it or not, and for a stdio server whether its command is on PATH. It is not
  drift.
