- Org overlay schema `team-harness.org/v2` (KAN-373; v1 still loads): `reviewers` with a GitHub team, `stages`
  with branches, and gate keys `approved_on: work`, `approvers`, `github_review`, `scope: repo`, `stage`,
  `approved_field` and `needs_approval: false`, plus `when: issue_types` and `when: projects`. `sync_shared.py`
  renders them into `release-approvals`; the example org is v2.
- The work-system PR check enforces v2 gates: stages by the PR's base branch, gates approved on the work ticket,
  Jira field values, and an approving review from a member of the approvers' GitHub team (new `review-token`
  input). Data a v2 rule needs that can't be read applies the gate or leaves it unverified.
- The tracker's normalised issue carries an optional `issue_type`, and `doctor.py` knows the v2 example's placeholders
  (`COMPANY-ORG`, `ESSPROJ`, `ARCHPROJ`, `CHGPROJ`).
