- `doctor.py --live` sends an MCP server's credential only to an `https://` endpoint (or plain http to localhost,
  127.0.0.1 or ::1): any other endpoint, or one with a user part (`x@host`), gets no request, and the server's check
  is a `fix` naming it ("endpoint is not https; doctor won't send the credential"), even when the credential is unset
  in that shell. Its `tools/list` follows no redirect: a 30x is reported with its status and the credential header
  never goes to where it points. Plain http to this machine bypasses every proxy (environment or system), which would
  otherwise get the header in clear text; https keeps the proxy, which only tunnels it. A credential with a line
  break or NUL (PowerShell's `Get-Content -Raw` keeps a CRLF) is not sent, and an error that could quote it is not
  shown.
