- `scripts/doctor.py` is one readable preflight for a fresh work laptop or a new teammate: one `ok`, `fix` or `skip` line per check, each fix with its exact command, exit 1 on any fix and `--json` for hangar and flightdeck. It checks Claude Code against the lock's version (and, with `--live`, that the lock's model answers), the interpreter the hooks run with and PyYAML, that each installed hook runs and each guard blocks with exit 2, the install against its manifest, the installed lock against its channel, a clean checkout, one harness per scope, the guide's `@import` line and a real (not symlinked) `settings.json`, each lock MCP server in `claude mcp list` (run from the project, so project-scope servers count) with the lock's transport and exact endpoint (with `--live`, one `tools/list` call to each header-token server), `gh auth status` with repo scope on the company host, that the company's org overlay is applied (no `placeholder: true` org and no placeholder value left in any installed skill), that the repository's test and check commands (`ai-dlc.toml` `[checks.commands]` or `--test-cmd`) are allowed and not stopped by an ask or deny rule, managed settings included (on Windows without Git Bash, by `PowerShell(...)` rules), and that `hangar trace import` and `flightdeck ingest` are ready for local capture. It writes nothing (except the transcript of `--live`'s one session) and prints no credential value. The work-laptop runbook and README run it after the install.
