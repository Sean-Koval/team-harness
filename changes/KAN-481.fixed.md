- `generated.yml` installs the same tools as `check.yml` (flightdeck and the ai-dlc CLI as well as hangar), so its
  post-merge checks no longer fail on the knowledge query test; a test holds the two workflows' tool refs equal
  (KAN-481).
- `generated.yml` checks out main with full history, as `check.yml` does. A shallow clone rendered suite-default's
  `env.stable.yaml` with today's bindings, which added the ai-dlc dependency to stable without a promotion; the next
  build after this merges takes it back out (KAN-481).
- The windows CI job now builds the generated files (locks, env files, candidate lines) with hangar in a venv of its own, from a full clone, before its tests. It built only the shared layer's copies, so on a PR that edits a hook the locks still pinned the old files and the installer tests failed.
- `build_generated.py`, `relock.py`, `render_envs.py` and `promote.py` read and write text as UTF-8 with LF line endings on every OS, so a local build on Windows writes the same files as CI.
- `relock.py` reads a harness's bindings file as UTF-8 too, and a test holds the four build scripts to UTF-8 reads
  and UTF-8 LF writes, so a new call can't slip back to the platform encoding (KAN-481).
