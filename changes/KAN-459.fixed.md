- The work-system hook guards an Atlassian server by its tools, whatever the server is named: a second Atlassian
  server added under another name, or a dispatcher carrying an Atlassian operation or `cloudId`, is judged as tracker
  and wiki, and a session binding can only add roles, never take one away (KAN-459).
- work-default names its Atlassian server `atlassian`, as suite-default does; its credential is
  `ATLASSIAN_MCP_AUTHORIZATION` (hangar credential `atlassian-mcp`). Skills reach Jira and Confluence by role
  (ai-dlc's `tracker_*` tools, or the tracker server), and a test keeps Atlassian tool names out of every skill.
- Upgrading a local work-default install: remove the old `jira` MCP server (`claude mcp remove jira`), add
  `atlassian` with the command `install_local.py` prints, and rename `JIRA_MCP_AUTHORIZATION` to
  `ATLASSIAN_MCP_AUTHORIZATION` (hangar credential `jira-mcp` to `atlassian-mcp`) wherever it was set.
